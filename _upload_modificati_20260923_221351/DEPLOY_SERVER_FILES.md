# File server da eliminare e ricaricare

Questa checklist serve per mettere online il sito PHP custom e far funzionare:

```text
/api/membership-request.php
```

Prima regola: fai sempre un backup della cartella del dominio prima di cancellare.

## Non eliminare mai senza backup

Non cancellare questi file/cartelle se contengono dati reali:

```text
.env
public/uploads/
uploads/
```

Non cancellare il database MySQL. Le migration vanno importate, non sostituite al database.

## Caso A: online c'e ancora WordPress

Se nella root del dominio vedi questi file/cartelle, il dominio sta usando WordPress:

```text
wp-admin/
wp-content/
wp-includes/
wp-config.php
index.php
xmlrpc.php
wp-login.php
wp-load.php
wp-blog-header.php
wp-cron.php
wp-settings.php
wp-mail.php
wp-links-opml.php
wp-trackback.php
license.txt
readme.html
```

Per sostituire WordPress con il sito PHP custom:

1. Scarica un backup completo della root WordPress.
2. Elimina dalla root del dominio i file/cartelle WordPress sopra.
3. Carica ed estrai lo ZIP creato con:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-deploy-zip.ps1
```

4. Dopo l'estrazione nella root devono esserci almeno:

```text
.htaccess
public/
src/
config/
```

5. Crea o lascia il file `.env` sul server con le credenziali produzione.
6. Importa la migration iscrizioni manualmente dal repository locale o da un pacchetto creato con `-IncludeDatabaseFiles`:

```text
migrations/2026_07_07_membership_requests.sql
```

## Caso B: online c'e gia il sito PHP custom

Se il server ha gia questo progetto, il modo piu sicuro e:

1. Fai backup.
2. Crea lo ZIP standard.
3. Estrai/carica lo ZIP sopra i file esistenti.
4. Non importare SQL.
5. Non cancellare upload.

Lo ZIP standard non contiene database, migration, `.env` o upload.

Puoi sovrascrivere/ricaricare:

```text
.htaccess
public/api/
public/admin/
public/assets/
public/*.html
public/*.xml
public/*.txt
src/
config/
tools/
*.html
*.xml
*.txt
robots.txt
sitemap.xml
```

Poi estrai lo ZIP nuovo nella stessa root.

Non eliminare:

```text
.env
public/uploads/
database esistente
```

Se vuoi tenere anche gli upload nello ZIP, crea il pacchetto con:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-deploy-zip.ps1 -IncludeUploads
```

Se un aggiornamento richiede modifiche al database, crea un pacchetto separato con i file SQL:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build-deploy-zip.ps1 -IncludeDatabaseFiles
```

Ma importa le migration solo manualmente e solo una volta.

## Test dopo upload

Apri:

```text
https://unfairedmotoclub.it/api/membership-request.php
```

Risultato atteso:

- deve rispondere JSON
- non deve mostrare una pagina WordPress
- non deve dire "Pagina non trovata"

Poi testa:

```text
https://unfairedmotoclub.it/iscrizione.html
```

Compila il form e controlla:

```text
https://unfairedmotoclub.it/admin/memberships.php
```

## Nota .htaccess provider precedente

Se nel file manager trovi un `.htaccess` con scritto:

```text
DO NOT EDIT THIS FILE
Create a new .htaccess file in your htdocs directory
```

non modificarlo direttamente: e un file di sistema del vecchio hosting.

Dentro la cartella `htdocs` del dominio devi invece caricare il `.htaccess` del progetto, quello incluso nello ZIP.

Su Server Plan, se il dominio punta gia alla root del sito, deve rimanere solo il `.htaccess` del progetto nella root pubblica del dominio. Eventuali `.htaccess` generati da un provider precedente vanno rimossi solo dopo backup.

Se devi crearlo a mano nella root pubblica, usa questo contenuto:

```apache
DirectoryIndex public/index.html index.php index.html
Options -Indexes
ServerSignature Off

<IfModule mod_rewrite.c>
  RewriteEngine On

  RewriteCond %{HTTPS} !=on
  RewriteCond %{HTTP_HOST} !^(localhost|127\.0\.0\.1)(:\d+)?$ [NC]
  RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [R=301,L]

  RewriteCond %{HTTP_HOST} ^unfairedmotoclub\.it$ [NC]
  RewriteRule ^ https://www.unfairedmotoclub.it%{REQUEST_URI} [R=301,L]

  RewriteRule ^(?:config|src|migrations|tools|tests)(?:/|$) - [F,L]
  RewriteRule ^(?:database\.sql|README\.md|GUIDA_PASSWORD_ADMIN\.md)$ - [F,L]
  RewriteRule ^\. - [F,L]

  RewriteRule ^img/(.*)$ public/assets/img/$1 [L]
  RewriteRule ^Doc/(.*)$ public/assets/docs/$1 [L]

  RewriteCond %{REQUEST_URI} !^/public/
  RewriteCond %{DOCUMENT_ROOT}/public%{REQUEST_URI} -f [OR]
  RewriteCond %{DOCUMENT_ROOT}/public%{REQUEST_URI} -d
  RewriteRule ^(.*)$ public/$1 [L]

  RewriteCond %{REQUEST_URI} !^/public/
  RewriteRule ^$ public/index.html [L]
</IfModule>

<IfModule mod_headers.c>
  Header always set Referrer-Policy "strict-origin-when-cross-origin"
  Header always set X-Content-Type-Options "nosniff"
</IfModule>
```
